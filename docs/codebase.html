papers コードベースの地図

人と AI が同じ「ペーパー」をブロック単位で書き換える共有キャンバス。Go のサーバー 1 本が Web UI・REST・WebSocket・MCP をまとめて出し、Firestore Enterprise に保存する。

2026-11-22 時点、ブランチ initial-implementation（モデル刷新の実装後）。モデルと概念の正本は docs/model.html、実装の設計は docs/design.html。これはコードを読む前の案内図。

全体の形

入口は 3 つあるが、行き先は 1 つ。ブラウザも AI も、最後は同じ usecase のメソッドを呼ぶ。権限の判定もそこで 1 回だけ行う。

入口誰が使うコード中身
Web UI人frontend/ → api.go, live.goReact の SPA。サーバーのバイナリに埋め込まれて配られる
REST /api/v1人（UI 経由）と AIcontroller/http/api.goワークスペース（読むだけ）、ペーパー、操作のまとまり、版、木、検索、添付、トークン
WebSocket /live開いているペーパーの画面controller/http/live.go他人の変更の受信だけ（サーバーからの一方向）

規模の目安は Go が約 13,500 行（テスト約 4,800 行）、フロントエンドが約 5,500 行。設定は --config のディレクトリ（ワークスペースごとの TOML と Rego）で、例は examples/。

層とパッケージ

上から下へ呼ぶ。下の層は上の層を知らない。保存先と外部サービスは domain/interfaces の口（ポート）の裏に隠れていて、use case はどの DB で動いているかを知らない。箱を押すと、その層の説明が出る。

中心の概念

覚える名詞は少ない。ワークスペースは設定ファイルにあり、保存先にはホームの記録だけ。ペーパーはブロックの並びで、子ペーパーは親の本文の paper ブロック。書いたものはすぐ「今の状態」になり、誰かが保存したときだけ「版」ができる。同時編集はロックではなく、ブロックの Rev で守る。

名前ひと言で定義
Principalリクエストしてきたユーザーと、使ったトークン（読み取り用か、どのワークスペースか）model/principal.go
Workspaces設定から読んだワークスペースと、使える人を決める Rego（60 秒キャッシュ）service/workspace
Actorブロックや版に残る「書いた者」。人・AI（代理元つき）・systemmodel/actor.go
Op / batch1 回のリクエストで送る操作の列。全部か無か。ref で新しいブロック・行・列を指すusecase/ops.go
Conflict元の Rev の後に他人が内容を変えていた op。まとまり全体が 409 で返り、現在の状態が付くusecase/ops.go

1 回の編集の旅

人がブロックを 1 つ書き換えて、別の人の画面に出るまで。ロックは取らない。手順のボタンで、その段階の矢印だけを浮かび上がらせる。

ほかの流れ

起動

papers serve は設定のディレクトリを読み（TOML の検証と Rego のコンパイル。1 つでも不正なら起動しない）、保存先・添付の保存先・usecase・controller の順に組み立てる。UseCases.Init が各ワークスペースのホームを作り（何度起動しても 1 つ）、毎時の処理が 30 日を過ぎたゴミ箱を消す。

ペーパーを開く

GET …/papers/{p} で本体とパンくず、/blocks?limit=200 で最初の範囲を受け取り、残りはカーソルで読み足す。範囲の中の paper ブロックが指す子は 1 回の一括取得で付く。続いて /live の WebSocket をつなぐと hello が届き、以後は変更フィードが流れる。/status で「v3 から変更あり」を出す。

版を保存する・戻す

「版を保存」は SaveVersion: 最新の版と同じなら何もしない。違えば変わったブロックだけ写し、版を書き、VersionNumber を進める。「この版に戻す」は RestoreVersion: 今の状態を版に合わせ、よそへ移った子は戻さない。画面は戻す前に保存していない変更を確かめる。

ログイン

/api/auth/login から Google に飛び、/callback で ID トークンを検証する（nonce と JWKS）。入口は許可したドメイン・メールで絞り、どのワークスペースを使えるかは各ワークスペースの Rego が決める。AI は画面の「トークン」で発行した pap_… を Bearer で送る。MCP は Bearer しか受けない。

検索

Search は Repository.Search に語を渡し、当たりのペーパーを一括で読んで、見えないもの・ゴミ箱・アーカイブを除く。「この配下で」は親を 1 段ずつ一括で辿って絞る。検索エントリは書き込みと同じトランザクションで書かれ、記法を除いた平文が入る。

AI が書く

MCP の papers_guide でワークスペースの決まりごととホームの本文を読み、papers_read（パスでも指定できる）で Rev を受け取り、papers_write で書く。区切りがついたら papers_save_version で版にする。HTML・SVG・Mermaid のブロックは AI だけが書け、UI は sandbox 付きの iframe（RichFrame）で描画するだけ。

フロントエンド

状態管理のライブラリは使っていない。開いているペーパーの状態は api/paperState.ts の純粋関数で更新する。ブロックは Rev を比べて古いものを捨てるので、操作の応答と変更フィードが同じ変更を二度運んできても壊れない。本文の編集はブロックごとに Tiptap（RichEditor）で行い、ブロックをまたぐ動き（Enter で分割、先頭の Backspace で結合、複数段落の貼り付け）は papers の操作にする。

守っている約束

コードを変えるときに破りやすいものだけ。全文は CLAUDE.md。

  • アクセスは use case で、Principal を通して判定する。 見えない相手には「存在しない」（404）を返し、存在を漏らさない。読み取り用トークンでの書き込みだけ 403。
  • ID はすべてサーバーが発行する。 クライアントが決められる ID はない。新しいものを同じまとまりで指すのは ref。
  • サーバーはメモリに状態を持たない。 Cloud Run で複数台動く前提。接続 1 本ぶんの状態と、設定（起動時に読む）だけはよい。配信は Firestore のリスナー頼み。
  • ロックは作らない。Rev で守る。 update・delete は元の Rev を必須にし、衝突は一度拒否する。UI は編集開始時の Rev を送る。
  • 版はシステムが勝手に作らない。 保存の操作だけが版を作る。
  • ペーパー本体を書き込みのたびに書かない。 更新時刻は 1 分に 1 回まで。中身はブロック側に持つ。
  • クエリを足したら索引も足す。 indexes.go の RequiredIndexes に書き、papers firestore setup で作る。
  • 読み取りは一括で。 子ペーパー・ピン・検索の当たりは GetPapers 1 回で読む。usecase のテストが読み取り回数を数える。
  • AI の HTML/SVG は RichFrame の中だけで描く。 本文の記法は React の要素として描き、HTML として差し込まない。
  • 保存先の契約テストは両方の実装で走る。 pkg/repository/*_test.go。記法の例は Go と TS の両方で走る。
  • 設計は HTML で書いて artifact にする。 モデルの正本は docs/model.html、実装の設計は docs/design.html。
